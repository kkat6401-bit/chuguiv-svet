# Свет · Чугуев, очередь 4.1

Сайт показывает график отключений света для Чугуева (очередь 4.1): статус сейчас, ближайшее отключение или включение, шкалу на сегодня и завтра, историю изменений и актуальность данных. Бесплатно: GitHub Pages + GitHub Actions. Ничего устанавливать не нужно.

## Установка (всё в браузере, около 15 минут, лучше с компьютера)

Старый сайт не трогаем: всё делаем в **новом** репозитории.

1. Зайдите на github.com под своим аккаунтом. Нажмите **+** справа вверху → **New repository**.
2. В поле Repository name введите, например, `chuguiv-svet`. Выберите **Public**. Нажмите **Create repository**.
3. На открывшейся странице нажмите ссылку **uploading an existing file**.
4. Распакуйте архив на компьютере. Перетащите в окно браузера **содержимое папки** (index.html, README.md, workflow-update.yml и папки css, js, scripts, data). Внизу нажмите **Commit changes**.
5. Создайте файл автоматизации. Нажмите **Add file → Create new file**. В поле имени введите точно: `.github/workflows/update.yml` (после каждого символа `/` появится папка). Откройте на компьютере файл `workflow-update.yml` в Блокноте, скопируйте всё содержимое и вставьте в большое поле. Нажмите **Commit changes** → **Commit changes**. Файл `workflow-update.yml` в корне после этого можно не удалять.
6. Разрешите Actions записывать данные: **Settings → Actions → General → Workflow permissions** → выберите **Read and write permissions** → **Save**.
7. Включите сайт: **Settings → Pages**. В разделе Build and deployment выберите Source: **Deploy from a branch**, Branch: **main**, папка **/ (root)** → **Save**.
8. Запустите первую проверку: вкладка **Actions** → слева «Обновление графика» → **Run workflow** → зелёная кнопка **Run workflow**. Через минуту обновите страницу: должна появиться зелёная галочка.
9. Адрес сайта: `https://ВАШ_ЛОГИН.github.io/chuguiv-svet/` (через 1–2 минуты после шага 7; точный адрес показан вверху страницы Settings → Pages).

Если на шаге 8 галочка красная, нажмите на запись запуска и пришлите мне текст ошибки.

## Как это работает
- Каждые ~10 минут Actions скачивает `Kharkivoblenerho.json` (репозиторий OE_OUTAGE_DATA), проверяет его (JSON, `fact.data`, `fact.update`, ключи-даты = полночь Kyiv, очередь `GPV4.1`, 24 значения из `yes/no/maybe/first/second`) и пишет `data/schedule.json` и `data/history.json`.
- Любая ошибка (сеть, пустой или битый JSON, откат к старой версии, неверный формат) оставляет последний корректный график нетронутым и показывается на сайте.
- **Достоверность** (высокая/средняя/низкая/нет) считается из нескольких признаков: возраст последней принятой проверки, подтверждался ли сегодняшний день источником, совпадает ли «сегодня» в источнике с реальным, не пропал ли день, не остановился ли парсер. Если данные старше 6 часов или графика на сегодня нет, статус показывается как «неизвестен».
- История хранит дату обнаружения, прежнюю принятую проверку, старый и новый варианты и список изменённых интервалов. Фиксируется появление графика, изменение и пропажа даты в источнике.
- Сайт читает данные прямо из вашего репозитория и сравнивает с копией на Pages, выбирая более свежую.
- Время: Europe/Kyiv. `first`/`second` = нет света первые/последние 30 минут часа; `maybe` показывается как «возможно отключение».

## Ограничения (честно)
- **Источник может быть неактуален.** Файл OE_OUTAGE_DATA при проверке 10.11.2026 содержал график на 08.10.2026 (дата парсинга 07.10.2026). Пока в нём нет графика на текущую дату, сайт показывает «Статус неизвестен».
- Дополнительные источники (outage-data-ua, bezsvitla, alerts.energy) не подключены: нет проверенного машиночитаемого адреса, и все они берут данные у Харьковобленерго. Сверки источников нет, сайт об этом пишет.
- В сутки перехода на летнее/зимнее время (29.03 и 25.10) часы источника сопоставляются с настенными часами, возможна неточность в 1 час.
- GitHub запускает расписание с задержкой (иногда 15–30 минут), 10 минут не гарантируются.
- Каждая проверка делает запись в репозитории (~144 в сутки), так задумано.
- Другие очереди и города: структура данных подготовлена (`QUEUE` в `scripts/update.mjs`), интерфейс пока только для 4.1.
- Папка `tests` нужна только для проверки кода, на работу сайта не влияет.
